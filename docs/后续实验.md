# 按教程逐步扩展

以下是后续实验方向，不是已经交付的功能或实验结论。

| 阶段 | 当前基础 | 可以加什么 | 用什么证据判断有用 |
| --- | --- | --- | --- |
| 最小 Agent | 工具循环、错误处理、步数上限 | 比较专用文件工具与只给 bash | 固定任务的成功率、重复错误、工具次数 |
| 上下文 | 长输出落盘、按需读取、字符预算 | 可控 compaction | 相同长任务中关键信息丢失率、token、成本 |
| 长任务 | 持久化轨迹和结果 | progress.md + feature_list.json + session 交接 | 重新启动后是否能准确恢复待办和验证状态 |
| 完成判断 | 用户提供的命令验证门 | 独立 evaluator | 统一人工真值下的精确率、召回率、成本 |
| 具身 Agent | 工具接口可扩展 | 仿真中的 VLA 工具、成功检测器 | 在固定任务集上分别统计规划、检测、执行失败 |
| 训练 | 结构化运行轨迹 | 清洗和标注轨迹后再讨论 SFT/RL | 保留测试集、数据合规、训练前后泛化表现 |

建议先建立约 10 个可重复的小任务：明确输入文件、期望行为、独立验收脚本。为每次运行保存模型 ID、配置、结果和失败原因。每项配置运行多次，不用单条成功轨迹推断某个组件有效。

如果实现 compaction，原来的“上一次输入是下一次输入前缀”不再成立，应明确记录压缩事件，并区分压缩前后的 append-only 区间。不能继续沿用旧测试后声称完全保持前缀缓存。

如果实现多 Agent，先定义子任务输入、输出、预算、错误处理和共享文件写入规则。多 Agent 并不会自动消除自评偏差，也可能增加成本和冲突。

如果接入 LIBERO/VLA，另外建立动作空间、图像观测和 oracle 使用边界。仿真器成功真值可以用于打分或上限对照，不能无说明地给所有 Agent 条件使用。当前代码没有机器人控制功能。
